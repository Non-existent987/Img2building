# 冷启动投放清单

零流量的本质不是"没推广"，是"没人知道它存在"。开源项目的流量来自主动投递，不是等着被发现。

按投入产出排序，从上往下做。

---

## 第一梯队：不依赖任何人批准，立刻能做

### 1. GitHub 仓库设置（10 分钟）

- [ ] **Topics 填满 15 个标签**（见 `github-setup.md`），这决定站内搜索曝光
- [ ] **Social Preview 换成自定义图**（见 `github-setup.md`），默认灰卡片转发出去完全没人点
- [ ] **仓库描述填满关键词**：中文"卫星影像 建筑物识别 深度学习 GIS"，英文 "Building extraction from satellite imagery"，GitHub 搜索靠这个
- [ ] **开启 Discussions**，把 Issue 分成 Q（提问）/ Feature（需求）/ Bug，互动痕迹本身就是活跃度信号

### 2. 录一段 30 秒演示视频（1 小时）

**这是单项投入产出比最高的一件事。**

内容脚本：
1. 0-3s：卫星底图 + 拖拽框选一段区域
2. 3-10s：模型推理中（进度条/loading）
3. 10-18s：蓝色建筑轮廓浮现
4. 18-24s：切换到街道图对照验证
5. 24-30s：导出 SHP，导出成功的提示

转成 GIF 放 README 首屏。GitHub README 支持 GIF 内联播放。

为什么必须做：文字描述让人需要想象，30 秒动画让人立刻理解"这东西能干什么"。遥感/深度学习圈子的信息流里，视频和 GIF 的停留时长是文字的 3-5 倍。

### 3. 补齐缺失的关键信息（1 小时）

- [ ] **量化效果对比图**：原图 / 识别结果 / 矢量导出，三联并排。这是唯一能让人信服的东西
- [ ] **识别精度数据**：IoU / 精确率 / 召回率，哪怕只测了一个区域也比没有强
- [ ] **一句限定的免责声明**："识别结果需人工校验" —— 这条反而会提升信任度

## 第二梯队：一周内完成，需要你花时间但不需要别人配合

### 4. 中文技术平台投稿（3-5篇，每篇改一下标题）

成稿见 `article-cn.md`，按平台调性微调后发布：

| 平台 | 特点 | 标题方向 |
|---|---|---|
| **CSDN** | 搜索流量大，权重高 | "用深度学习从卫星影像批量提取建筑轮廓" |
| **知乎** | 长文效果好，讨论区能引流 | "如何批量获取一片区域的建筑物矢量数据？" |
| **掘金** | 开发者精准度高 | "卫星影像建筑物自动提取：技术方案与开源实现" |
| **SegmentFault** | GIS/后端读者多 | "前端实现在地图上框选并导出 SHP" |

注意：**每个平台都要改标题**，不要复制粘贴。搜索引擎会识别重复内容，全平台同标题同文等于互相竞争。

### 5. 视频平台（1-2 条）

B站和抖音是这两年最大的技术流量池，且对个人号友好。

- B站：3-8 分钟，讲清楚"怎么做"和"效果如何"，标题带关键词
- 抖音/小红书：30 秒纯演示流，配"卫星影像自动提取建筑物"的说明文字
- 视频比文章传播广得多，**同一个演示视频可以同时供 README、B站、抖音用**

### 6. 部署在线演示站

README 里的演示链接必须是**活的**。死链是最劝退的开源项目特征。

免费方案（都是免备案、免信用卡）：

| 平台 | 配置 | 国内访问 |
|---|---|---|
| **Cloudflare Pages**（推荐） | 绑 GitHub 仓库，构建命令 `npm run build`，输出目录 `frontend/vue_project/dist` | 优于 GitHub Pages |
| **Vercel** | 同上 | 一般 |
| **EdgeOne Pages** | 同上（腾讯云） | 好 |
| **GitHub Pages** | 需手动推 dist | 一般 |

构建配置（Cloudflare Pages）：
```
构建命令:    cd frontend/vue_project && npm ci && npm run build
输出目录:    frontend/vue_project/dist
Node版本:    18.17.0
```

⚠️ **重要限制**：目前后端 `backend/` 是空的，App.vue 的按钮没有接API。所以现在能部署的只是个空壳界面，**交互功能全是死的**。

要么先按上面把界面传上去（至少页面能打开，比死链强），要么等后端写完再部署。**不要把空壳部署上去然后宣称是能用的工具**——那比死链更糟，会消耗掉仅有的一点信任。

### 7. 投 Awesome 列表（一天）

遥感 / GIS 圈子有明确的社区索引，进了列表就有持续被动流量：

- [Awesome-Remote-Sensing](https://github.com/polvi/rs-samples)
- [Awesome-Deep-Learning-for-Remote-Sensing](https://github.com/ZHO-ZS-Zhou/awesome-deep-learning-for-remote-sensing)
- [Awesome-GIS](https://github.com/shaunlgs/awesome-gis)
- [Awesome-Geospatial](https://github.com/shaunlgs/awesome-geospatial)
- OpenGeoHub

投法：Fork 对应仓库 → 在 README 分类下加一行 → 提 PR。一句话说明 + 一个链接即可。

## 第三梯队：长期，慢但有效

### 8. 参与社区讨论

- QGIS 中文社区论坛、GIS 派、地理信息开发者QQ群
- Reddit: r/gis, r/remote sensing, r/ComputerVision
- 知乎 / V2EX 相关话题
- Discord: 遥感、GIS、QGIS 相关服务器

**不要一上来就发广告**。策略是：先回答别人的技术问题，建立可信度；当别人提到建筑物提取需求时，再提你的项目。同一句话，第一天说是广告，第十天说就是推荐。

### 9. 建立对比评测

如果你同时用过商业 API、QGIS 插件、其他开源工具，写一篇横向对比（准确性、速度、成本、数据合规）。这类内容在搜索上极有价值，因为对比词本身就是长尾关键词。

### 10. ModelScope 魔搭发布模型

魔搭的模型库是国内 AI 从业者找模型的第一站。挂上去不只是"存个文件"，而是：

- 模型卡片带 Task 标签，出现在对应任务搜索结果里
- 可以直接在线体验
- 有独立的浏览量和下载量统计

国内用户下载 HF 权重需要走 hf-mirror 镜像，魔搭直连，这两个平台各放一份是标准做法。

## 时间线预期

| 阶段 | 时间 | 预期 |
|---|---|---|
| 仓库设置 + 视频 + 文章首发 | 第 1 周 | 0 → 10-50 star（取决于技术圈传播力度） |
| Awesome 列表 + 多平台分发 | 第 2-4 周 | 累计 50-200 star |
| 社区参与 + 对比评测 | 第 2-3 月 | 稳定小规模用户，开始收到 Issue 反馈 |

**冷静预期**：遥感 + GIS + 深度学习这个交集在国内不算大，垂直但精准。这不是一个能爆的项目，但能精准积累行业用户——而这类用户一旦用起来，粘性很高，因为他们有真实业务需求。20 个真正在用的人，比 2000 个 star 有价值。

不要用互联网产品的增长标准来衡量它。
